# MedBrains 3.33.2

**Release date:** not yet released. **Licence:** GNU AGPL-3.0-only, or a commercial
licence.

A security and fix update to 3.33.0. Update every install.

3.33.1 was tagged but never published, because its desktop builds failed. Rather
than move a version tag that people may already have seen, it was replaced by
3.33.2, which contains everything 3.33.1 did plus the fixes below.

## Before you update

If your install was set up with a deploy kit older than 3.33.1, **rotate your
backup key** after updating. Older kits sealed backups to the MedBrains project's
own key instead of your hospital's. The full steps are in the
[changelog](https://github.com/medbrains/medbrains/blob/v3.33.2/CHANGELOG.md),
under 3.33.1.

## Security

- Backups are sealed to your hospital's own key.
- An authenticator code is accepted once only, and requests for sign-in and
  booking codes are limited.
- Consent and document signatures recorded as a one-time code are refused.
- Dependency fixes, including Bouncy Castle 1.86 in the Android app.

## Added

- A signed container image for x86-64 and arm64 (the 3.33.0 image did not build).
- `medbrains-proxy` in the server tarball.
- OS hardening: services confined with AppArmor, the image scored against the CIS
  benchmark, and boot health on the console.
- A download page on the website for every OS image and app.
- A documentation home page that starts from your role, and a public
  [test report](https://tests.medbrains.in).

## Fixed

- The desktop apps build again.
- The eye exam form checks the axis and cylinder together before saving.
- Background file reads and writes no longer slow the server.

## Changed

- The IT security officer role can view and manage backups.
- A fixed [release calendar](https://github.com/medbrains/medbrains/blob/main/medbrains/docs/COMPATIBILITY.md):
  a monthly patch day and quarterly feature releases.

The complete list is in the
[changelog](https://github.com/medbrains/medbrains/blob/v3.33.2/CHANGELOG.md).
