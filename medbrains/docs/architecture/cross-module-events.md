# Cross-Module Event Contract

Status: v1 implementation baseline, 2026-05-04

## Purpose

MedBrains modules must not infer cross-module side effects from ad-hoc status strings or duplicate capture tables. A source workflow records the real clinical or operational fact, then emits one typed event. Cascades, NABH evidence sinks, dashboards, outbox workers, and live UI refreshes subscribe to that event.

## Envelope

Every cross-module event must carry this metadata:

| Field | Required | Notes |
|---|---:|---|
| `tenant_id` | yes | Tenant boundary and RLS context. |
| `event_name` | yes | One value from `ClinicalEventName`. |
| `source_module` | yes | Canonical module that owns the source write. |
| `source_record_id` | yes | Primary record that caused the event. |
| `actor_id` | yes | Authenticated user or service principal. |
| `occurred_at` | yes | UTC timestamp generated by the server. |
| `patient_id` | no | Required only when the event is patient scoped. |
| `admission_id` | no | Required only when the event is admission scoped. |
| `encounter_id` | no | Required only when the event is encounter scoped. |
| `department_id` | no | Used for department-scoped refresh and RLS. |
| `payload` | yes | Event-specific minimal facts. |

Rust source of truth: `crates/medbrains-core/src/clinical_events.rs`

TypeScript mirror: `packages/types/src/index.ts`

Server helper: `crates/medbrains-server/src/events.rs`

## Usage Rules

1. New route code must use `ClinicalEventName`, not raw event-name strings.
2. The source workflow remains authoritative. Evidence tables mirror source facts and link back with `source_module` plus `source_record_id`.
3. Events that must commit atomically with the source write use `queue_clinical_event_in_tx`.
4. Events that only trigger in-process pipelines use `emit_clinical_event`.
5. Payloads must include the required keys listed above. The server helper rejects incomplete payloads before publishing.
6. Event names are append-only. Do not rename an event after production use; add a new event and keep the old subscriber until the migration is complete.

## Example

```rust
use medbrains_core::clinical_events::{ClinicalEventEnvelope, ClinicalEventName};

let event = ClinicalEventEnvelope::new(
    claims.tenant_id,
    ClinicalEventName::PharmacyOrderDispensed,
    order_id,
    claims.sub,
    serde_json::json!({
        "order_id": order_id,
        "patient_id": patient_id,
        "items": items,
    }),
)
.with_patient(patient_id);

crate::events::queue_clinical_event_in_tx(&mut tx, &event).await?;
```

## Next Wiring Targets

First route conversions should be high-signal source events:

- Pharmacy dispense: emit `pharmacy.order.dispensed`.
- OPD encounter creation: emit `opd.encounter.created`.
- Lab result completion: emit `lab.order.completed`.
- Billing invoice creation/finalization: emit billing events.
- IPD bed assignment, bed transfer, discharge initiation/completion.
- Quality incident, code blue, transfusion reaction, equipment downtime, BMW disposal.
